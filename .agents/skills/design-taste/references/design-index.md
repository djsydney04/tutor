## Choose a reference for a task

1. Identify the surface: landing page, editorial page, commerce, or working app.
2. Start with the target's existing brand and content. Choose one reference whose
   communication problem resembles the task, then inspect the relevant section.
3. Name the principle to transfer and its benefit. For example, use real output
   to explain a developer tool, or align specifications to support comparison.
4. Keep a second reference only when it resolves a specific remaining choice.
   A collage of all seven brands will not create a coherent direction.
5. Translate the principle to the target's content, constraints, and components.
   A dramatic homepage treatment may be unsuitable for frequent operational work.

## Add or refine an entry

Update this file when the user requests maintaining the index or provides a new
preference in a task authorizing library changes. Ordinary reference browsing
does not authorize publishing edits to this shared library.

Keep the confirmed preference separate from the reviewer's interpretation.
For a new bookmark, record the URL, surface, and why it was supplied; leave visual
observations pending. For an inspected example, add:

- Exact URL and section or app state; the reason it is useful.
- User-confirmed likes/dislikes, or an explicit "not yet specified."
- What was observed, the date, viewport, and screenshot path/link when available.
- The transferable principle, suitable contexts, and cases where it would clash.
- Source/asset attribution where needed. A bookmarked site is not an asset license.

Refine this index in place; avoid duplicate brand lists in persona or project
skills. Capture only permitted material, without customer data or credentials.
